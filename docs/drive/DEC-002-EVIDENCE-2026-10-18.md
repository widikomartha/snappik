## Official references and findings

All URLs accessed **18 October 2026**. Findings are paraphrases of official documentation, not observed API behavior. No third-party source used.

| Reference | Finding and investigation implication |
|---|---|
| [Workspace credentials](https://developers.google.com/workspace/guides/create-credentials) | API keys provide anonymous public-data access; OAuth requires user consent. Service identities can receive explicit file/folder sharing; Cloud IAM alone does not grant Workspace file access. This does not prove anonymous folder discovery |
| [Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) | `drive.file` is per-file/non-sensitive; no whole existing/new subtree guarantee established here. `drive.readonly` permits reading/downloading accessible files and is restricted; server storage/transmission entails security assessment. App eligibility and review outcome remain unknown |
| [Resource keys](https://developers.google.com/workspace/drive/api/guides/resource-keys) | Link access can require a key; direct user/group access differs from domain/anyone discovery. Request/read root and child `resourceKey`, use `X-Goog-Drive-Resource-Keys`. Correct key is not proof of permission or list completeness |
| [files.list](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list) | Maximum page size 1,000, fewer entries possible; follow next tokens. Rejected tokens require restarting staged traversal. Results can change across pages; `incompleteSearch` means missing results. Method documents OAuth scopes, so general API-key guidance alone cannot settle anonymous listing |
| [Search files](https://developers.google.com/workspace/drive/api/guides/search-files) | Parent query enumerates immediate children; recurse through separately validated folders and preserve provider IDs/path components. Do not substitute a global name search |
| [Shared Drive support](https://developers.google.com/workspace/drive/api/guides/enable-shareddrives) | Use `supportsAllDrives`, `includeItemsFromAllDrives`, resolved drive ID and narrowed corpus. Flags do not grant membership/domain permission or bypass restricted descendants |
| [Limited-access folders](https://developers.google.com/workspace/drive/api/guides/limited-expansive-access) | Metadata may be readable while `canListChildren=false` and child listing is empty. This is a false-completeness risk. Check capability, not an empty list alone. The page has inconsistent boolean wording in one explanatory sentence; rely on the explicit capability semantics and verify on fixtures |
| [Download blobs](https://developers.google.com/workspace/drive/api/guides/manage-downloads) | `files.get` with `alt=media` returns blob bytes; precheck `capabilities.canDownload`. Metadata visibility alone does not authorize bytes. Application MIME/extension/50 MiB/decoder policy still applies |
| [Error handling](https://developers.google.com/workspace/drive/api/guides/handle-errors) | Distinguish permission/not-found, rate reasons and transient failures. 404 is not proof a file never existed. A broad retry on all 403s would be wrong |
| [Drive limits and pricing](https://developers.google.com/workspace/drive/api/guides/limits) | New quota model from 1 May 2026: 1,000,000 units/min/project; 325,000/min/user/project; 1 TB/day egress; 400,000,000-unit daily billing threshold. Previously active projects can retain quotas. `files.list` 100 units, `files.get` 5, `files.download` 200; `alt=media` accounting not independently verified. Standard use described at no additional cost; over-quota charges planned later in 2026 with notice, no complete future tariff established. Assigned project quota/billing unknown |
| [OAuth web-server flow](https://developers.google.com/identity/protocols/oauth2/web-server) | Offline access/refresh supports workers; check actual granted scopes. Revocation affects the user's grants across clients under the project and can take time to propagate. Separate Drive/login project is a proposed containment boundary, not tested isolation |
| [OAuth token expiration](https://developers.google.com/identity/protocols/oauth2#expiration) | External consent in Testing normally yields seven-day refresh tokens for Drive scopes; tokens also expire/revoke for other reasons. A successful short spike is not production longevity evidence |
| [OAuth best practices](https://developers.google.com/identity/protocols/oauth2/resources/best-practices) | Secure server credentials, encrypt tokens at rest, check unpredictable state, request scope in context and handle denial/revocation; no browser/localStorage refresh-token design |
| [Workspace user-data policy](https://developers.google.com/workspace/workspace-api-user-data-developer-policy) | Limited Use covers derived sensitive/restricted-scope data; disclose purpose/transfers/deletion and secure it. Cache-header restrictions are explicit. A private cache or a seven-day application TTL alone establishes no permitted retention |
| [Google API terms, §5/§8](https://developers.google.com/terms) | Nonpublic data exposure needs explicit opt-in; content/derivative/cache restrictions and termination deletion apply, with stated permission/law qualifications. Require review of thumbnail creation, client delivery and retained confirmation metadata; do not claim either blanket prohibition or blanket permission |

**Prepared protocol, Not run:** after a new chat explicitly authorizes a dedicated owned fixture and secret-manager configuration reference, begin with two My Drive roots, one public and one private. Manifest: root has three tiny valid generated JPG/PNG/WebP blobs, a nested folder with a duplicate filename under a different ID, and an empty folder; record stable ID/path/size/hash only in private test storage. Have the fixture owner identify any key-required root/child. Creating/sharing fixtures and OAuth consent are separate owner-authorized actions; no existing personal or competitor folder is a substitute.

First read-only pass per credential mode: **at most 30 Drive requests, 10 MiB total source bytes, 120 seconds**, concurrency one, no automatic retries/fallback identity. Stop on budget, auth uncertainty or malformed response; do not call failure an empty tree. This small manifest does not exercise the production 50 MiB ceiling. Required request recipes (parameters URL-encoded by the client; all identifiers are private test references):

1. `GET https://www.googleapis.com/drive/v3/files/{rootId}?supportsAllDrives=true&fields=id,name,mimeType,trashed,parents,resourceKey,driveId,inheritedPermissionsDisabled,capabilities(canListChildren,canDownload)`; verify folder, not trashed and child-list capability under the selected identity. Try key-required references without/correct/wrong key, within budget.
2. `GET https://www.googleapis.com/drive/v3/files` with `q='{folderId}' in parents and trashed=false`, `pageSize=2`, `corpora=user`, `supportsAllDrives=true`, `includeItemsFromAllDrives=true`, explicit `nextPageToken,incompleteSearch,files(...)` metadata fields above plus `size,version`; exhaust tokens then recurse. Attach root/current-folder key header when present. Compare the entire manifest; stable IDs disambiguate names. API key belongs only to its public mode; OAuth Bearer only to its consented mode. Never log either.
3. `GET https://www.googleapis.com/drive/v3/files/{fileId}?alt=media&supportsAllDrives=true`, with the file's resource key if needed, fixed origin/no redirects, fresh `canDownload`, byte cap/cancellation and expected MIME/size/hash. Capture sanitized status, timing, response cache directives and content length/count. Test private root metadata/list/media negatives with API key independently; no leaked entries or false complete empty scan.
4. Record mode, sanitized config reference, principal alias, root alias, timestamp, request count, page lengths/tokens-present flags, observed ID/path manifest match, hash match, capability presence, safe status/reason, cache directives and exclusions.
