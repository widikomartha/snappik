## Failure limits and watch-outs

Revocation COMMIT uncertainty returns 503; a retry establishes certainty. If no revocation committed, an existing session can work after DB recovery, and UI must not claim logout success. Already authorized/committed in-flight responses cannot be recalled; every new authorization/stale mutation rechecks under user lock. Native cleanup may leave a row until retry, but app metadata denies it; missing metadata cannot default to success. Single-session logout does not revoke upstream SSO/all devices or prove copied pending challenge revocation. Default local web has two pools (at most 2×DB_POOL_MAX); production capacity/roles and auth schema packaging remain unverified. Preserve app→studio→project→selection lock order and immutable subject mappings; never merge on email or silently delete duplicates.
