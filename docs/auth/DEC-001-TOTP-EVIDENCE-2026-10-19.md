## Implementation and observed guarantees

- [Auth006](../../src/db/auth-migrations/006_totp_challenge_security.sql) adds digest-keyed lifecycle receipts, version/expiry/revocation and optional resulting session FK. [Challenge module](../../src/modules/auth/challenge.ts) validates native HMAC signature/canonical cookies, registers, validates and cancels proofs. New table contains no raw cookie/identifier/code/password. Duplicate relevant cookies400; invalid signature cannot cancel another proof.
- [HTTP wrapper](../../src/modules/auth/http.ts) serializes logout, login, TOTP and reset using the existing PG credential gate. It commits session/receipt/native-proof cancellation together before200 or cookie clearing; pending proof cannot read protected APIs. Native consumption remains mandatory; replay401. Step-up/enrollment requires an active app session, including when native cleanup previously failed.
- [Library hook](../../src/modules/auth/library.ts)/[security metadata](../../src/modules/auth/security.ts) bind a pending completion to its receipt atomically with app session metadata, using a per-library async scope and app-user lock. Version mismatch/expired/revoked/already-bound receipt cannot receive new metadata. Native transaction and app hook are not one DB transaction; unissued orphan rows can remain after hook failure, but a correctly signed orphan cookie is explicitly denied without metadata. Fresh primary login is required after consumed/uncertain completion; no automatic replay/restamping/adoption.
- [Reset](../../src/modules/auth/recovery.ts) marks receipts revoked within the existing password/token/version/all-session transaction. Suspension remains restricted studio state, not global account revocation. No public factor-management, OAuth, operator bootstrap or sender endpoint added.
- Cleanup removes<=32 old inactive receipts on issuance; receipts for live resulting sessions survive even past challenge expiry. Lazy physical retention is not an idle-time deletion guarantee. Existing global/account/canonical-proof budgets and native limits remain enabled with unchanged thresholds.
