# ADR-005: Drive and hosting feasibility for DEC-002/003

Date: 15 October 2026. Status: conditional proposal; DEC-002 and DEC-003 **open**. Scope: BL-002 only. No provisioning, account access, paid service, deployment or provider selection performed.

## Context and evidence

Local source of truth: master / `641a3ee` at inspection, clean worktree. Existing code is only the isolated BL-001 auth spike; no root app manifest, web/worker or migrations. User confirmed no authorized dedicated Drive test folders are available and requested synthetic work. [Adapter contract](../drive/ADAPTER_CONTRACT.md) and [evidence/protocol](../drive/BL-002-EVIDENCE.md) accompany 29 passing offline checks. Documentation observations below are not observed provider behavior in Snappik.

## DEC-002: access modes and conditional recommendation

| Mode | Official basis / hypothesis | Current support disposition |
|---|---|---|
| API key + anyone-with-link My Drive folder | API keys provide anonymous public-data access, not private user authority. Test metadata, full listing and blob reads independently; a browser-visible folder is insufficient evidence. [Workspace credentials](https://developers.google.com/workspace/guides/create-credentials) | Candidate for public-only pilot, **unproved** including resource-key folder listing. Do not force private sources public |
| Studio OAuth + private My Drive or directly shared folder | Prefer minimum adequate scopes. `drive.file` is per-file access via app/Picker; do not assume selecting a parent grants existing/new nested files. `drive.readonly` reads/downloads broadly and is restricted; server storage/transmission entails verification/security-assessment obligations. [Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) | Candidate if public-only access is insufficient. Folder-wide sufficiency, ongoing refresh, scope approval, assessment cost and owner experience remain unproved; no consent flow added |
| OAuth + Workspace Shared Drive | Distinct from a shared My Drive folder. Scope/root-bound query uses drive ID, `supportsAllDrives` and `includeItemsFromAllDrives`; avoid `allDrives` incomplete scans. [Shared Drive API](https://developers.google.com/workspace/drive/api/guides/enable-shareddrives) | Candidate only after separate authorized Workspace fixture; membership, limited-access folders and domain policy may deny access |
| Dedicated service account explicitly shared test folder | A separate identity must have actual access. It is not the studio owner and not a universal private-folder bypass | Not selected; no domain-wide delegation, impersonation or arbitrary credential fallback |
| Browser cookie/link scraping, export HTML, download-confirmation pages | Undocumented transport cannot establish bounded API behavior | Unsupported; no implementation or testing |
| Shortcuts, Google Docs/native exports, RAW/HEIC/GIF/video/ZIP, inaccessible/restricted blobs | Outside current JPG/JPEG/PNG/WebP blob slice; skip/count shortcuts and unsupported entries | Unsupported in this slice, with explicit exclusions/errors |

Recommendation: retain an explicit credential-mode seam. Validate API-key public access first on a dedicated test folder if that product mode is acceptable; compare isolated OAuth on the same synthetic tree before selecting a model. Do not infer that a logged-in Google Snappik account has Drive scopes, or silently upgrade to broad OAuth. Root metadata success, public download success and complete folder discovery are different tests. Resource keys require the documented [header](https://developers.google.com/workspace/drive/api/guides/resource-keys), even though directly authorized users may not need one.

The current Google [quota guide](https://developers.google.com/workspace/drive/api/guides/limits) publishes quota units, with 1,000,000/minute/project, 325,000/minute/user/project, a 1 TB daily egress threshold and 400,000,000 daily quota-unit billing threshold; it warns of planned over-quota charges later in 2026. `files.list` costs 100 units, `files.get` 5; do not assume the separate `files.download` cost exactly describes `files.get?alt=media`. Actual project quotas can differ. These are documentation observations on this date, not an assigned Snappik quota or permission to enable billing. Use quota telemetry, budgets and 403/429 backoff; do not deliberately saturate a live project to prove throttling. Blob-download quota/abuse restrictions require separate failure UX.

Permitted private thumbnail caching is **not closed** by successful listing. Document purpose/disclosure, minimum access, revocation/deletion, cache retention and applicable [Workspace user-data policy](https://developers.google.com/workspace/workspace-api-user-data-developer-policy) review. The seven-day idle BR retention is a proposal, not a Google permission grant. DEC-006 remains separate.

## DEC-003: hosting proposal and alternatives

Conditional topology: one always-on Node web service and one independent worker from the same build, managed PostgreSQL in the same region, private derived-object storage, managed secrets, private scratch and external backup retention. Start evaluating Render Singapore for web/worker/PostgreSQL; evaluate private R2 APAC storage only if its location model meets the approved residency needs. Nothing is provisioned or selected.

| Candidate | Evidence / feasible direction | Material limit / missing evidence |
|---|---|---|
| Render web + continuous background worker + paid PostgreSQL | [Web services](https://render.com/docs/web-services) support Node/Docker and private service networking; [workers](https://render.com/docs/background-workers) run continuously. This matches the two-process baseline; PostgreSQL polling is application logic, not a Render durability promise | No actual proxy timeout, 50 MiB binary stream, cancellation, shutdown/lease/restart or cold-start measurement. Official web page inspected does not establish the needed proxy/idle limit; treat it as unknown, not unlimited |
| Render Singapore | Listed among [regions](https://render.com/docs/regions); co-locate web/worker/DB. Proposed pilot pool budget: 10 web + 5 worker connections with migration/ops reserve | No Jakarta region listed in the inspected page. Cross-border suitability, availability at purchase, latency from Indonesian networks, replicas and backup locations need review; no residency claim |
| Render paid DB backups | [Recovery documentation](https://render.com/docs/postgresql-backups) provides PITR: 3-day window on Hobby, 7 on Pro+. Restore creates a new DB for isolated verification | Neither equals the baseline 30-day retention. Add daily encrypted logical exports retained 30 days with separate restricted storage, restore/revocation reconciliation and drill. RPO <=24 h / RTO <=4 h remain targets, not results |
| Cloudflare R2 private thumbnails | [Pricing](https://developers.cloudflare.com/r2/pricing/): Standard $0.015/GB-month, $4.50/million Class A and $0.36/million Class B; no R2 egress fee. Keep public access off; server only, scoped credentials, protected app media path | [APAC location hint](https://developers.cloudflare.com/r2/reference/data-location/) is a best-effort placement preference, not a Singapore/Indonesia residency guarantee. Jurisdiction controls are a separate mechanism. No bucket/privacy/IAM/deletion latency/cache smoke performed |
| Vercel web + external worker/DB/private storage | [Function limits](https://vercel.com/docs/functions/limitations) list 4.5 MB request/response payload and finite duration; official [guidance](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions) identifies streamed responses as an option | Buffered 50 MiB original is unsuitable. Do not equate the buffered cap with a universal streaming prohibition: prove this exact binary route/runtime. A continuous PostgreSQL polling worker still needs separately justified hosting; this combined topology adds providers and region/pool coordination |
| Single VPS/container host + PostgreSQL + private object service | Architecturally plausible: Node processes and controlled scratch/streams; no provider chosen or current plan verified | Team owns patching, restart supervision, TLS, backups, separate failure domains and restoration. Low advertised VM price is not full operations cost. Not selected |

[Render compute documentation](https://render.com/docs/compute-plans) now uses plan IDs such as `0.5c-512mb` (legacy Starter) and `0.1c-256mb` (legacy Basic-256mb DB, 100 connections). 512 MB is a price-floor comparison, not adequate image-decoder evidence. Start sizing a worker for measurement with >=2 GB RAM and bounded decoder concurrency, rather than promising two large decodes fit in 512 MB. Web and worker scale independently; no autoscaled replica may multiply DB pools or provider concurrency without a shared budget.

Indicative lower bound from the official [Render cost discussion](https://render.com/articles/how-much-does-cloud-application-hosting-cost-for-small-businesses) ($13/month web+small DB as of July 2026) and [indexed pricing table](https://render.com/pricing?trk=article-ssr-frontend-pulse_little-text-block) ($7/month small compute): roughly $20/month for two smallest compute units plus smallest paid DB, **before** DB storage, larger worker, bandwidth, backup storage, workspace fees/tax/domain/monitoring. The live pricing page's dynamic table did not render fully in this inspection, so this is an indicative floor, not a current quote or a validated pilot budget. Refresh the actual region/plan quote and define a spending ceiling before authorization. Free tiers are not evidence for durable worker/backups or production reliability.

## Capacity hypotheses, not benchmarks

- At 5,000 × 50 MiB, a project may reference 244.14 GiB of originals. Do not preload originals into RAM or duplicate all of them into permanent storage. One full thumbnail generation still downloads/decodes source bytes; two passes approach 488.28 GiB before user downloads.
- Assuming one 150 KiB derived thumbnail, 5,000 thumbnails are 732.42 MiB (~0.768 GB); the PRD 100 × 1,000-photo pilot is ~15.36 GB before transform variants/overhead/backups. These are synthetic sizing assumptions, not measured compression ratios. R2 storage cost alone would be ~15.36 × $0.015 = $0.23/month before any free allowance/rounding; operations and app egress remain separate.
- 50 simultaneous 50 MiB transfers require 2.44 GiB of scratch plus overhead if all admitted. Candidate admission cap two transfers/process consumes <=100 MiB source scratch plus overhead, with explicit queue/busy behavior; not 50 buffered originals in web RAM. Fifty 50 MiB downloads are 2.44 GiB outbound traffic; object egress pricing does not eliminate web proxy bandwidth cost.
- Decoded pixels can vastly exceed compressed size. File cap alone does not bound decoder memory; dimension/pixel/CPU ceilings need synthetic valid/hostile images and a pinned production decoder. Signature-only tests do not establish decode feasibility.
- A 50 MiB source at 1 Mbit/s takes ~419 seconds before overhead; 120-second spike timeout intentionally fails such an attempt. Hosting total duration must cover preflight plus client delivery, or cap/rate/timeout UX must be explicit. No silent retry after emitting bytes.
- Five pages of 1,000 entries are only a best case for a flat 5,000-image folder. Empty pages, many subfolders and actual provider visibility change request cost. Technical traversal budgets can reject a sparse tree before the image ceiling; surface that failure clearly.
- PRD load fixture is 10 studios/100 projects, 1,000 images/four folders reference, 50 client sessions. Save/confirm p95 <1 s and warm first thumbnail batch <3 s require measured app/DB/network results; they cannot be derived from a local 50 MiB disk write.

## Decision and closure conditions

Keep both gates open; accept only the bounded synthetic seam for further independent work. No product scope is broadened. Current API/schema key/credential gaps are recorded in the adapter contract; integrate the paired changes only after credential choice. BL-003/007/008/013/017 remain separate work.

DEC-002 closure requires the authorized matrix in [evidence](../drive/BL-002-EVIDENCE.md), explicitly supported/excluded modes, actual scope/resource-key/visibility/revocation outcomes and approved credential/cache policy. DEC-003 closure requires chosen region/plans and budget, reproducible deployment commands from an actual app/build, verified 50 MiB proxy/timeout/cancel path, durable worker/PostgreSQL evidence, private object access and backup/restore drill. No gate closes from documentation or mocks.

Reconsider after real permission/quotas differ, stricter residency requirements, failed decoder/streaming load or changed provider prices/limits. Affected references: Architecture, Deployment, decision register, Test Plan, Traceability, Backlog and agent state/handoff; public API and logical persistence remain unchanged in this spike.
